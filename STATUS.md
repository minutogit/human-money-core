## Known Issues

- **PROTOCOL HARDENING V3 (BREAKING, 2026-08-26)**: The `HMC_TX_AUTH_V3` signature digest (`calculate_l2_payload_hash_raw`) now binds two additional essential fields: (1) `layer2_voucher_id` (hex id for spends, canonical `"none"` placeholder for genesis locks — a genesis lock cannot bind its own derived id without circularity) and (2) the canonical privacy-guard commitment (`privacy_guard_commitment`: SHA3-256 of the Base64 guard payload, empty string when absent). This changes the byte preimage of every internal transaction signature, fingerprint and L2 lock request; all previously issued V3 signatures/fingerprints are invalidated and legacy foreign fingerprints are purged on load/cleanup (same coordinated wire migration as the V2 upgrade). Regression-proof: `tests/security_audit_module_02_crypto.rs::audit_02_11_*`, `tests/security_audit_module_04_integrity.rs::sa04_08_*`.
- **RESOLVED HMC-SEC-02-11 / audit_02_11 (MEDIUM, CWE-347/345)**: Lock-entry transplant between vouchers closed by the voucher-id digest binding above: `process_l2_verdict` now verifies the lock-entry signature over a digest containing `layer2_voucher_id`, so an authentic lock observed on voucher A fails verification when relabeled onto victim voucher B (previously only an out-of-band string comparison guarded this and a MITM server could drive quarantines with context-free evidence). Genesis lock entries are reliably detected via the reserved `"none"/"none"` shard pair (spends can never carry it since HMSEC-SA06-11). Regression-proof: `tests/security_audit_module_02_crypto.rs::audit_02_11_*` (un-ignored, green).
- **RESOLVED HMSEC-SA04-08 (CRITICAL, CWE-347)**: Privacy-guard equivocation is now attributable: the guard commitment is digest-bound (see protocol hardening above), `TransactionFingerprint` carries `privacy_guard_hash` (+ `layer2_voucher_id`) so two handovers of ONE input under two different guards produce DISTINGUISHABLE fraud evidence instead of collapsing byte-identically, and `check_for_double_spend` gained an equivocation rule: same-ds_tag buckets whose entries share one `t_id` but diverge in any signature-bound evidence field are surfaced as verifiable conflicts (prerequisite for attribution/quarantine). The guard-swapped twin additionally fails chain validation outright. Regression-proof: `tests/security_audit_module_04_integrity.rs::sa04_08_*` (un-ignored, green).
- **RESOLVED HMSEC-SA06-07 (HIGH, CWE-347)**: Trust Assertion spec (`protocols/trust/1.0/assertion.md`) hardened BEFORE any verifier implementation ships: `assertion_id = hash(canonical_json({issuer_id, subject_id, trust_level, context, timestamp}))` and `issuer_signature` over the id bytes, so every semantic field is transitively committed; verifiers recompute-and-compare and reject any divergence. Previously trust_level/context were cryptographically unprotected (undetectable forgery of WoT statements). Regression-proof: `tests/security_audit_module_06_privacy.rs::sa06_07_*` (un-ignored, green).
- **RESOLVED FIELD_MODULUS_LE (HIGH, CWE-20)**: `trap_manager::FIELD_MODULUS_LE` byte 0 corrected from `0xEC` to `0xED` (base field prime p = 2^255 - 19, NOT the group order); `ensure_canonical_y`/`validate_shard_structure` now accept the legitimate coordinate y = p - 1 while rejecting y >= p as non-canonical. Regression-proof: `tests` unit tests `test_canonical_y_boundary_values`, `test_validate_shard_structure_accepts_max_canonical_point`.
- **RESOLVED ENDORSEMENT REPLAY (MEDIUM, CWE-345)**: `add_resolution_endorsement` verifies BEFORE the signature gate that `endorsement_id` equals the canonical SHA3-256 hash over the endorsement's own content fields (`proof_id`, `victim_id`, `resolution_timestamp`, `notes`). A genuinely signed endorsement minted for conflict A can no longer be attached verbatim to foreign conflict B (cross-proof attachment); B remains unresolved (`KnownOffender`). Regression-proof: `tests/wallet_api/conflict_management.rs::test_endorsement_replay_onto_foreign_proof_is_rejected`.
- **DEFENSE-IN-DEPTH JWE (LOW, CWE-697)**: All three X25519 Diffie-Hellman call sites in `secure_container_manager` (recipient key wrapping, sender double-key-wrapping, trial-decryption unwrapping) now reject non-contributory results via `.was_contributory()`, so low-order/small-order point targets fail closed instead of deriving KEKs from collapsed all-zero shared secrets.

- **RESOLVED HMSEC-SA01-01 (HIGH, CWE-349)**: `resolve_conflict_offline` no longer lets unauthenticated gossip fingerprints win the offline "Earliest Wins" race: the winner race is restricted to fingerprints whose `t_id` corresponds to a locally-held transaction. Previously an attacker could poison any bundle with a forged sibling fingerprint (same ds_tag, attacker-chosen `t_id`, `encrypted_timestamp` decrypting to 0 since the XOR key is publicly derivable from `prev_hash + t_id`) and remotely quarantine the victim's legitimate voucher (`"Lost offline race"`). Path-reunion detection (both forks local) is unaffected; remote-only branches remain exclusively handled by the gated `import_proof` path. **V2 update (2026-08-25)**: with self-authenticating fingerprints, FOREIGN fingerprints that verify against the `HMC_TX_AUTH_V2` digest (signed by the holder of the revealed ephemeral key) are deliberately re-admitted to the race for instant quarantine — the attacker class shrinks from "any external peer" to actors who ever held the output's private ephemeral one-time key, mathematically indistinguishable from a genuine double spend. Regression-proof: `tests/security_audit_module_01_traps.rs::f01_*`.
- **RESOLVED HMSEC-SA01-02 (MEDIUM, CWE-347)**: `verify_trap` now parses the Schnorr response scalar via the strict canonical parser (`Scalar::from_canonical_bytes`) instead of `from_bytes_mod_order`; non-canonical encodings `(R, s+l)` are rejected, closing proof malleability and aligning `s` handling with the existing U-scalar invariant. Regression-proof: `tests/security_audit_module_01_traps.rs::f02_*`.
- **RESOLVED HMSEC-SA01-03 (HIGH, CWE-345)**: `import_proof` enforces a new attribution-consistency gate: if `offender_id` parses to a did:key public key, both stored Schnorr trap proofs must verify against it (root-account format first, then the prefix derived from the claim itself, so prefixed SAI accounts are attributable too). Previously the anti-framing invariant documented on `ProofOfDoubleSpend.offender_id` was enforced only at creation time, letting a real double-spender sign a structurally genuine report that framed an innocent did:key identity and — combined with a backdated fork timestamp — quarantined the framed party's local branch. Anonymous/`ephemeral:` identifiers carry no attribution claim and skip the gate. Fixture hardening: `role_integration.rs` forks now carry valid traps bound to the claimed offender (production reality). Regression-proof: `tests/security_audit_module_01_traps.rs::f05_*`.
- **RESOLVED HMSEC-SA01-04 (LOW, CWE-354)**: `verify_stored_proofs_against_identity` no longer skips transactions whose attacker-influenced `t_type` contains "placeholder"; synthetic placeholders are excluded structurally via missing `trap_data` only. An offender can no longer type one real fork to drop below the >=2 verified-trap attribution threshold. Regression-proof: `tests/security_audit_module_01_traps.rs::f06_*`.
- **RESOLVED HMSEC-SA01-05 / AUDIT-01-F03 (LOW, CWE-20)**: RESOLVED by the V2 protocol upgrade (2026-08-25): `calculate_l2_payload_hash_raw` now hashes length-prefixed inputs under the domain tag `HMC_TX_AUTH_V2` via `crypto_utils::get_raw_hash_from_slices`, eliminating the former ambiguity of unprefixed concatenation of its leading string fields. This was a coordinated wire-format migration: existing V1 `layer2_signature`s/fingerprints are invalidated and legacy foreign fingerprints are purged on load/cleanup.
- **RESOLVED HMSEC-SA06-02 (CRITICAL, CWE-347)**: `open_and_verify_bundle` now recomputes both integrity bindings from the received bytes before any signature verification: `container.i == hash(canonical(container with i=""/signature=""))` and `bundle.bundle_id == hash(canonical(bundle with bundle_id=""/sender_signature=""))`. A stolen `(bundle_id, sender_signature)` / `(i, signature)` tuple can no longer be grafted onto manipulated bundle content (spoofed notes/timestamps/profile names or injected gossip fingerprints). Regression-proof: `tests/security_audit_module_06_privacy.rs::sa06_02_*` passes.
- **RESOLVED HMSEC-SA06-01 (HIGH, CWE-359/202)**: Private-mode bundles no longer carry a plaintext Ed25519 envelope signature made with the sender's PERMANENT identity key. `create_and_encrypt_bundle` omits `SecureContainer.signature` when the transferred transaction chain is fully anonymous (the signature was publicly verifiable against `i`, turning every "anonymous" transfer into a de-anonymization oracle for anyone holding a candidate public key). The receiver skips envelope-signature verification only when the field is empty; authenticity remains enforced by the inner bundle signature. Regression-proof: `tests/security_audit_module_06_privacy.rs::sa06_01_*` passes.
- **RESOLVED HMSEC-SA06-03 (HIGH, CWE-311)**: The "no plaintext financial payloads" fuse is now also enforced on the RECEIVE path: `open_and_verify_bundle` rejects any `TransactionBundle` container with `EncryptionType::None`, so hand-crafted cleartext containers can no longer be processed end-to-end by a core wallet (previously only honest senders were constrained at creation time). Regression-proof: `tests/security_audit_module_06_privacy.rs::sa06_03_*` passes.
- **RESOLVED HMSEC-SA06-04 (MEDIUM, CWE-617/125)**: Removed the remotely reachable index panics on attacker-supplied vouchers (`voucher.transactions[0]`) in `Wallet::create_detached_signature_response` and `process_and_attach_signature`; empty transaction chains now yield a graceful `ValidationError::InvalidTransaction` instead of aborting the host process. Regression-proof: `tests/security_audit_module_06_privacy.rs::sa06_04_*` passes.
- **ARCHITECTURAL DECISION HMSEC-SA06-05 (CORE-004)**: Direct counterparty DIDs are intentionally retained in the owner's encrypted local ledger (`TransferSent` and `TransferReceived` events) even during Stealth/Private Mode. *Rationale:* In an offline peer-to-peer cash network, hop-by-hop double-spend investigations require local records of the immediate transaction partner. The transaction chain and network transport container remain fully anonymous to third parties. Invariant enforced by: `tests/security_audit_module_06_privacy.rs::sa06_05_*`.
- **RESOLVED HMSEC-SA06-06 (MEDIUM, CWE-347/20)**: JWS profile verification now pins the `typ` header exactly like `alg` (rejecting type-confusion headers) and delegates did:key parsing to the canonical `crypto_identity::get_pubkey_from_user_id`: trailing-garbage aliases (`did:key:z<key><extra>`) are rejected as non-canonical identity strings, while prefixed SAI user IDs (`prefix@did:key:z...`) now import successfully (interop fix — exporting and re-importing one's own profile previously failed). Regression-proof: `tests/security_audit_module_06_privacy.rs::sa06_06_*` passes.
- **RESOLVED HMSEC-SA05-01 (HIGH, CWE-312)**: `FileVoucherArchive` now seals every archived voucher state into an encrypted envelope (`hmc-archive-v1`: ChaCha20-Poly1305 over canonical voucher JSON; keys via PBKDF2-HMAC-SHA512 from the wallet password with fresh random per-record salts, or a raw derived key via `with_key`). Plaintext constructor removed; legacy plaintext records remain readable via read-only fallback. Regression-proof: `tests/security_audit_module_05_storage.rs::sa05_01_*` passes.
